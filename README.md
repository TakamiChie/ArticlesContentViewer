# おんぷ村 コンテンツビューアー

添付のSCHEME.sqlに合わせたSQLite閲覧用アプリです。HTML / CSS / JavaScriptのみで構成し、ローカルサーバーにNode.jsを使用します。npmパッケージのインストール、ビルド、Python、PHPは不要です。

## 起動

1. Node.js 24.x以降をインストールします。
2. ZIPを展開し、content-viewerフォルダーでターミナルを開きます。
3. 次を実行します。ファイルパスは実際のSQLiteデータベースに置き換えてください。SCHEME.sql自体を指定するものではありません。

```powershell
node server.js "C:\Users\takam\Documents\contents.sqlite"
```

4. ブラウザーで http://127.0.0.1:8787 を開きます。終了はターミナルでCtrl+Cです。

ポートを変更する場合:

```powershell
node server.js "C:\path\contents.db" 8888
```

最初に架空のサンプル65件で確認する場合:

```powershell
npm run demo
```

生成されるdemo.sqliteは架空のデータで、実際の番組や再生可能なエピソードは含みません。既存のdemo.sqliteは上書きしません。

## 使い方

- 全種類のコンテンツを30件ずつ表示。配信元・source_type・並び順で絞り込めます。
- タイトル、llm_summary、llm_tagsを部分一致検索。空白区切りはAND条件。英字の大小・全角半角はNFKC正規化して検索します。「%」「_」はワイルドカードではなく文字そのものです。
- 検索欄の下には、llm_tagsをコンテンツ件数付きで集計した検索可能なタグ選択欄を表示します。タグを選ぶと検索欄へコピーし、LLMタグを対象に検索します。
- カードにはLLM概要・LLMタグを表示。LLM概要がない場合は元のsummaryを表示します。この代替summaryはLLM概要検索の対象ではありません。
- タグをクリックするとタグ検索。llm_tagsはJSON文字列配列、カンマ・読点・改行区切りに対応します。その他の形式は文字列として表示します。
- タイトルを押すと詳細表示。LISTENの https://listen.style/p/番組/エピソード 形式のURLは指定の178pxプレイヤーを埋め込みます。その他のコンテンツは実ページへのリンクを表示します。
- 詳細では元の概要、LLM概要、タグ、VTTも確認できます。DB内のHTMLは実行せず文字列として表示します。
- チェックを入れた内容はページ切り替えや検索後も保持します。「このページを選択」は表示中の最大30件が対象です。画面の再読み込み・終了で選択は解除されます。
- リンク一覧、生成したまとめはMarkdownファイルとしてダウンロードできます。選択した項目に文字起こし（`transcript_vtt`）がある場合は、記事タイトルを見出しにして選択順に連結した1つのテキストファイルとして保存できます。保存先はブラウザーの設定に従います。

## LM Studioとの接続

1. LM Studioで使用するモデルをロードし、ローカルAPIサーバーを起動します。
2. このアプリの「LLM接続設定」を開きます。
3. ベースURLに `http://127.0.0.1:1234/v1` を入力します。
4. 「モデル一覧を取得」を押し、設定を閉じてから「まとめる視点」の下にあるモデルID欄で選択します。入力済みでも候補を開くと全モデルを確認でき、手入力も可能です。認証を有効にしている場合はAPIキーも入力してください。
5. 設定を保存し、2〜100件選択して「選択した内容をまとめる」を押します。

OpenAI互換の `/v1/models` と `/v1/chat/completions` に対応したローカルサーバーで使用できます。Ollamaの互換APIを使う場合は通常 `http://127.0.0.1:11434/v1` を指定します。自動モデル取得が使えない場合はモデルIDを手入力してください。

ブラウザーからLM Studioへ直接アクセスせず、このNode.jsサーバーが仲介するため、LM Studio側でブラウザー向けCORS許可を設定する必要はありません。接続先は同じPCのlocalhost / 127.0.0.1 / [::1]のみ許可します。

URLとモデルIDはブラウザーに保存します。APIキーは保存せず、再読み込みで消えます。別PCのLLMやクラウドAPIへの接続には対応していません。

## まとめの入力と制限

- 入力は選択記事のタイトル・llm_tags・llm_summaryです。llm_summaryがなければsummaryを使います。文字起こし全体や音声はLLMに送信しません。
- 概要もない記事はタイトルとタグのみを使い、完了時に注意を表示します。
- 1件の概要は先頭8,000文字まで。省略した場合は通知します。
- 合計が約12,000文字を超える場合は分割して要約し、統合します。資料番号とURLは出力と一緒に保存します。
- 1回のAPIリクエストのタイムアウトは10分。画面の中止で接続を切断しますが、LLM側での計算停止の挙動はサーバーに依存します。
- コンテキスト長はモデルごとに異なります。トークンの厳密な計算はしていません。コンテキスト超過の場合はモデルの設定を増やすか、選択件数を減らしてください。分割閾値はserver.jsの12000で調整できます。
- 出力は最大2,000トークン。上限で途切れた応答は完了扱いにせずエラーにします。推論モデルが思考で上限を消費する場合は推論を無効にするか、server.jsのmax_tokensを調整してください。
- 元のLLM概要も生成結果も原発言ではありません。掲載前に音声・原文で確認してください。入力資料を命令として扱わないようプロンプトを指定していますが、出力の正確さを保証するものではありません。

## データベースの扱い

- SQLiteのARTICLEとSOURCEを直接LEFT JOINします。画像のない記事やSOURCEが欠落した記事も表示します。
- 既存のarticle_list / link_item_listは画像必須でLLM列がないため使用しません。
- SQLiteは読み取り専用で開き、query_onlyも設定します。スキーマ変更、要約の書き戻しは行いません。
- DBをクロール処理と共有する場合はSQLiteのロックが発生することがあります。安定した閲覧が必要なら、クロールを止めた時点のコピーまたはSQLiteバックアップを使用してください。WAL動作中のファイルを単独でコピーすると未反映データが欠落するため、SQLite対応のバックアップ方法を使用してください。
- 各検索時にDBを読み直します。「更新」で新しい記事を取得できます。配信元の追加はブラウザー再読み込みで反映します。DBファイル自体を交換した場合はサーバーを再起動してください。
- 検索は部分一致の全件走査です。数千件程度を想定しています。超大規模DBではFTS等を追加する余地があります。
- ローカルサーバーは127.0.0.1のみで待機し、公開配信用途には対応しません。DBファイルをHTTPで配信しません。LISTENプレイヤーとカバー画像の読み込みにはインターネット接続が必要です。

## ファイルと検証

- `server.js`: SQLite読み取り・検索API・LLM API中継
- `public/index.html`, `public/style.css`, `public/app.js`: 日本語UI
- `demo.js`: 架空のサンプルDB作成
- `SCHEME.sql`: 提供スキーマのコピー
- `test/app.test.js`: 添付スキーマを使用した統合テスト

```powershell
npm test
```

Node.js 24.19.0で、画像なし／配信元欠落を含む全件取得、ページ分割、日本語検索、全半角検索、特殊文字、SQLパラメーター、読み取り専用、詳細取得、接続先制限、異なるOriginの拒否、模擬LLMでのモデル取得・生成・分割要約と統合を検証しています。ブラウザー実機での画面操作はこの配布環境では未検証です。実際のユーザーDB、LM Studioの推論品質、LISTEN実音声再生はこの配布環境では未検証です。
